# RidTheWann Performance 0.5.0-beta — Release Candidate Notes

**Status:** candidate source on main; GitHub tag/release publication is pending.  
**Date:** 2026-10-16  
**Version:** 0.5.0-beta

## Highlights

- Redesign the native Tauri desktop experience for nontechnical players: Home, a separate preparation countdown, recording, analysis wait state, understandable results, history/Before-After, and Settings.
- Keep technical controls, the user-supplied PresentMon path, raw evidence and low-level numbers behind Advanced / Expert details.
- Add a managed-output capture entry point and a preflight summary for Windows permission, component readiness and the selected process.
- Show a generic native “Measurement complete” notification after a completed session, and localize Stable notification copy in Indonesian or English without application/PID/path identity.
- Add a Tauri close-request guard and clearer stopped-early / failed-result handling while keeping existing command paths and persisted schemas intact.
- Add comparison selection from one history list and preserve the existing three comparison statuses without creating new analysis thresholds.

## Compatibility and scope

- PresentMon remains user-supplied according to ADR-0028. RWP does not bundle, download or silently install executables.
- Capture remains out-of-process. No DLL injection, process hooks, overlay or remote UI assets are added.
- The CLI, analysis rules, rule versions, thresholds, report/manifest schemas and deterministic analysis behavior are intended to remain unchanged.
- The application still uses vanilla HTML/CSS/JavaScript under the existing Tauri CSP; no frontend framework or new dependency is introduced.

## Known limitations and validation status

- This release candidate has not completed its packaged Windows manual GUI smoke test in this task. In particular, the minimized countdown, native notifications, close-request lifecycle, high-DPI/accessibility and actual PresentMon capture require installed Windows validation.
- Real capture/hardware acceptance and the existing RC-05 sampler-overhead target gap remain open in STATE.md. This UX work does not close the v1.0 hardware acceptance criteria.
- The installer remains unsigned unless a signing artifact is produced separately; expect Windows SmartScreen's unknown-publisher warning.
- The GitHub tag/release is not published yet. Do not treat this candidate as a stable v1.0 release.
