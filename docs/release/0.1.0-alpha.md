# rwp 0.1.0-alpha — Release Notes

Version stays `0.1.0` (alpha). This is NOT v1.0. Single-device validated,
unsigned installer, PresentMon user-supplied.

## What rwp is

RidTheWann Performance (rwp) is an evidence-based gaming and streaming
performance analyzer for Windows 11. It correlates frame timing with system
state, detects reproducible failure patterns, and explains evidence without
treating a heuristic score as probability.

Capability order: Measure -> Analyze -> Diagnose -> Compare -> Explain ->
Recommend -> Optimize. The engine is deterministic and offline-first. Capture
is out-of-process: no DLL injection, game hook, or overlay dependency. See
`README.md`, `docs/methodology.md`, and `docs/limitations.md`.

## What works in this alpha

CLI (`docs/cli-reference.md`, failure taxonomy `docs/cli-errors.md`):

- `rwp doctor --presentmon C:\Tools\PresentMon.exe` (preflight; `--bundle` for a redacted diagnostic bundle)
- `rwp import-presentmon capture.csv --process-id 42 --qpc-frequency-hz 10000000 --output-dir sessions/run`
- `rwp analyze --session sessions/run --output-dir sessions/run-analyzed` (includes diagnosis; preserves V2 detector and interruption flag)
- `rwp report --session sessions/run-analyzed --format md` (`json|md|html`, default redacted)
- `rwp compare --baseline sessions/a --candidate sessions/b --same-scenario` (single and `--pairs <dir>` paired inference)
- `rwp calibrate --pairs <dir>` (A/A calibration recommends the equivalence margin)
- `rwp migrate --session sessions/legacy --output-dir sessions/migrated` (legacy report/session normalization; migration never recomputes diagnostics)

GUI (native Tauri app): live capture session configuration (PresentMon path
browse, process picker or PID, duration 1-3600 s, interval 10-5000 ms, default
50 ms), live progress with backend session events, session history
(manifest-verified), two-session Compare, report export, and failure
remediation. Manual checklist: `docs/acceptance/gui.md`.

## Install steps (NSIS, Windows-only)

> Released artifact for this alpha is the **offline installer bundle**
> (~208.94 MiB; WebView2 runtime embedded per ADR-0029). The smaller default
> bootstrapper bundle was not rebuilt in this batch — do not expect a ~2 MB
> file from this release.

1. Build or obtain the NSIS bundle locally per `docs/release-packaging.md`
   (binaries are never committed; hashes recorded in
   `docs/autopilot/STATE.md`). The installer is per-user (no elevation).
2. Run the installer. Because the alpha installer is unsigned, Windows
   SmartScreen shows an "unknown publisher" warning — this is expected (see
   Known Issues).
3. Supply your own `PresentMon.exe`: pick it via Browse in the GUI live-session
   configuration, or pass it to `rwp doctor --presentmon <PATH>`. rwp never
   silently redistributes or downloads PresentMon (see ADR-0028).
4. WebView2 runtime ships inside the offline installer bundle (see ADR-0029);
   first-run provisioning beyond that path is unverified.

## Quickstart (same as README)

```powershell
rwp doctor --presentmon C:\Tools\PresentMon.exe
rwp import-presentmon capture.csv --process-id 42 --qpc-frequency-hz 10000000 --output-dir sessions/run
rwp analyze --session sessions/run --output-dir sessions/run-analyzed
rwp report --session sessions/run-analyzed --format md
rwp compare --baseline sessions/a --candidate sessions/b --same-scenario
rwp migrate --session sessions/legacy --output-dir sessions/migrated
```

Legacy reports or sessions go through `rwp migrate` (see
`docs/troubleshooting.md`). Full command reference: `docs/cli-reference.md`.
Error codes: `docs/cli-errors.md`. GUI: build and run the native app, pick the
PresentMon executable, choose a live target process, set duration/interval,
and Start capture.

## KNOWN ISSUES (facts already in docs only)

- Installer is unsigned: SmartScreen "unknown publisher" warning is expected.
  Signing awaits a certificate/service (`docs/release-packaging.md`,
  `docs/limitations.md`).
- PresentMon is user-supplied; live capture is GUI-only, Windows-only — there
  is no `rwp capture` CLI yet (`docs/limitations.md`, `docs/cli-reference.md`).
- Full process/thread probing has high overhead on heavy targets (ADR-0027:
  mean 18.855 ms, p99 28.352 ms at 50 ms cadence over 12,000 ticks); the
  system-only mode is the low-overhead option (0.016 ms mean); the RC-05
  release target (<=1% total CPU, p99 <=2 ms) is not met yet
  (`docs/adr/0027-sampler-overhead-single-device-baseline.md`,
  `docs/methodology.md` §7).
- Validation is single-device only; there is no real PresentMon fixture set
  and no hardware acceptance matrix yet (`docs/limitations.md`,
  `docs/autopilot/STATE.md` BLOCKED_ON_USER, RC-07/RC-12).
- The `streaming_overhead` diagnostic never fires (no encoder telemetry);
  ETW/cycle-time cross-checks have not run (need an admin session)
  (`docs/limitations.md`).
- Evidence scores are heuristics, not probabilities; A/B comparison is
  descriptive-only and never causal proof (`docs/limitations.md`,
  `docs/methodology.md`).
- Threat-model owner sign-off is pending (`docs/threat-model.md`); auto-update
  is OFF by design (ADR-0030).
